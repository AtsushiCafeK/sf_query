# OAuth 2.0 接続設定（接続アプリの作成）

画面右上の「**Salesforceに接続**」ボタンを使えるようにするための設定手順。
一度**管理者が1回だけ**接続アプリを作れば、あとは各ユーザーが自分のアカウントでログインできる。

## なぜこの方式か

| | 内容 |
|---|---|
| 方式 | **OAuth 2.0 認可コードフロー + PKCE** |
| 利点 | ユーザーが自分のSalesforceログイン画面で認証するため、**アプリはパスワードを一切扱わない** |
| 複数ユーザー | ユーザーごとに個別のトークンが発行され、**その人の権限・共有ルールがそのまま適用される** |
| 固定トークン不要 | リフレッシュトークンで自動更新（期限切れは自動リトライ） |
| SOAP不使用 | ユーザー名＋パスワード＋セキュリティトークン方式は使わない |

---

## 手順1: 外部クライアントアプリケーションを作成する

> ℹ️ 最近作成されたSalesforce組織では、従来の「接続アプリケーション（Connected App）」の新規作成が
> 既定で無効化され、後継の **外部クライアントアプリケーション（External Client App）** に置き換わっている。
> OAuth 2.0 認可コードフロー + PKCE の使い方・エンドポイント・Consumer Key はどちらも同じで、
> **アプリ側のコード変更は不要**。

1. 設定（⚙️）→ 検索ボックスに「アプリケーションマネージャ」→ **アプリケーションマネージャ**
2. 右上の **新規外部クライアントアプリケーション**
   （「新規接続アプリケーション」ボタンが無いのが正常）
3. **基本情報** を入力
   - 外部クライアントアプリケーション名: `稟議書ダウンローダ`（例: `ringi_pdf_all_download`）
   - API参照名: 自動入力のままでよい
   - 取引先責任者メール: 自分のメールアドレス
   - 配信状態: `ローカル`
4. **API (OAuth 設定の有効化)** セクションで **☑ OAuth 設定の有効化** にチェック
   → チェックするまでURL・スコープの入力欄は表示されない
5. **アプリケーション設定**

   | 項目 | 値 |
   |---|---|
   | コールバック URL | `http://localhost:8080/oauth/callback` |
   | 選択した OAuth 範囲 | `API を使用してユーザーデータを管理 (api)`<br>`いつでも要求を実行 (refresh_token, offline_access)` ← **2つとも必要** |

   > コールバックURLは `config.yaml` の `salesforce.oauth.redirect_uri` と**完全一致**させること。
   > 末尾スラッシュやポート番号の違いでもエラーになる。

6. **フローの有効化**（❗️見落としやすい・必須）

   | 項目 | どうする |
   |---|---|
   | **認証コードおよびログイン情報フローを有効化** | **☑ 入れる** |
   | クライアントログイン情報フロー / デバイスフロー / JWT ベアラーフロー / トークン交換フロー | チェック不要 |

7. **セキュリティ**

   | 項目 | どうする |
   |---|---|
   | Web サーバーフローの秘密が必要 | **⬜ 外す**（PKCEの公開クライアントにする） |
   | 更新トークンフローの秘密が必要 | **⬜ 外す** |
   | サポートされる認証フローに **PKCE** 拡張を要求 | **☑ 入れる** |
   | 更新トークンのローテーションを有効化 | ☑ でも可（アプリ側は新トークンを保存して対応済み） |

8. **保存** → 「変更が有効になるまで最大10分かかります」と表示されるので少し待つ

### ⚠️ IP 制限に注意（複数ユーザー運用時）

「**OAuth Web サーバーフローの信頼済み IP 範囲**」に値が入っていると、**その IP からしか認証できない**。
在宅勤務や別拠点のユーザーは接続に失敗するため、複数ユーザーで使うなら**空にする**か、
利用する全拠点の IP 範囲を登録する。（社内からのみ許可したい場合は意図的に残す）

## 手順2: Consumer Key を config に設定

1. 設定 → **外部クライアントアプリケーションマネージャー** → 作成したアプリを開く
2. **設定** タブ → **OAuth 設定** → **「コンシューマー鍵と秘密」** ボタン
3. 表示された **コンシューマー鍵（Consumer Key）** をコピー
4. [config/config.yaml](../config/config.yaml) に貼り付ける

```yaml
salesforce:
  auth_mode: "oauth"          # ← 本番運用時は oauth に切り替える
  oauth:
    client_id: "3MVG9..."     # ← コピーしたコンシューマー鍵
    client_secret: ""         # ← PKCE公開クライアントなので空のままにする
    redirect_uri: "http://localhost:8080/oauth/callback"
```

> **`client_secret` は空にしておく。** 手順7で「秘密が必要」のチェックを外した公開クライアント構成では
> 秘密は使わない。ローカルアプリに秘密情報を持たせないことがPKCEを使う目的でもある。
> `config.yaml` は `.gitignore` 済みだが、鍵の類はコミット・共有しないよう注意する。

## 手順3: 接続する

```bash
poetry run python src/app.py
```

1. <http://localhost:8080> を開く
2. 右上の **「Salesforceに接続」** をクリック
3. Salesforceのログイン画面 → ログイン → **「許可」**
4. アプリに戻り、右上が **● 接続中：あなたのユーザー名** に変わる

以降は検索・ダウンロードがそのユーザーの権限で実行される。
**切断**ボタンでトークンを失効（revoke）できる。

---

## `auth_mode` の使い分け

[config/config.yaml](../config/config.yaml) の `salesforce.auth_mode`:

| 値 | 動作 | 用途 |
|---|---|---|
| `oauth` | OAuth接続が必須。未接続なら接続を促す | **本番運用**（配布時の既定） |
| `cli` | sf CLI パススルー。画面には「開発用接続」と表示 | 開発中。接続アプリ不要で即動く |

`auth_mode: cli` のままでも「Salesforceに接続」ボタンは使え、**接続した場合はOAuthが優先される**。
（OAuthセッションがあればそちら、無ければCLIにフォールバックする）

## つまずいたときは

| 症状 | 原因と対処 |
|---|---|
| `redirect_uri_mismatch` | 接続アプリのコールバックURLと `config.yaml` の `redirect_uri` が不一致。完全一致させる |
| `invalid_client_id` | Consumer Key の貼り間違い、または作成直後で反映待ち（最大10分） |
| `state が一致しません` | ブラウザのタブを複数開いて認証した場合など。もう一度接続し直す |
| 接続アプリの設定が反映されない | 保存後10分ほど待つ。それでも駄目なら接続アプリを参照して設定を再確認 |
| ログイン先がSandbox | `config.yaml` の `salesforce.login_url` を `https://test.salesforce.com` に変更 |
